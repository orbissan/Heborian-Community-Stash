ZÁKLADNÍ PRAVIDLA
Každá funkce má vlastní adresář, ID, konfiguraci a implementaci. Registrace
je explicitní seznam, nikoliv vyhledávání dalších pluginů/reflexí. Není zde
síťová synchronizace ani další modifikační framework uvnitř BepInEx/SPT.
Serverové a klientské projekty se vzájemně nereferencují.

Konstruktor modulu pouze převezme závislosti, nemění hru. Inicializace běží
jednou po startu; zapínání a konfigurace se projeví až po restartu. Moduly
nepřistupují přímo ke stavu jiných modulů. Potřebují-li společnou službu,
předá se explicitně konstruktorem nebo kontextem. Případnou komunikaci mezi
serverem a klientem navrhneme až pro konkrétní funkci.

SERVEROVÝ MODUL
1. Vytvořte Modules/<Id>/<Id>Module.cs a <Id>Options.cs.
2. Options obsahuje Enabled=true a vlastní nastavení. Přidejte vlastnost
   se stejným ID do ServerConfiguration a příklad do config.example.json.
3. Implementujte IServerModule. IsEnabled čte pouze svoji sekci konfigurace.
   InitializeAsync nejprve zkontroluje všechna nastavení a potřebná data,
   teprve potom provede úpravy v paměti pomocí příslušných API SPT.
4. Označte modul [Injectable(InjectionType.Singleton)] a potřebné služby SPT
   přijímejte konstruktorem. Přidejte parametr do konstruktoru HeborianServer
   a instanci do jeho pole modules. Ostatní moduly se nemusí upravovat.
5. Přidejte test vypnutého modulu, vlastní konfigurace a zachování dat mimo
   jeho odpovědnost. Ověřte přesné API proti instalaci SPT 4.1.6.

Příklad tvaru nové sekce v ServerConfiguration:
  public ExampleOptions Example { get; set; } = new();

Příklad rozhraní modulu (ukázka, nikoliv registrovaná funkce):
  public string Id => "Example";
  public bool IsEnabled(ServerConfiguration c) => c.Example.Enabled;
  public Task InitializeAsync(ServerConfiguration c, CancellationToken token)
  {
      token.ThrowIfCancellationRequested();
      // Validace, poté zamýšlená úprava dat pouze v paměti.
      return Task.CompletedTask;
  }

ServerModuleHost loguje Disabled, Loaded nebo FAILED s ID. Výjimka jednoho
modulu neblokuje další; zrušení pomocí CancellationToken se propaguje.
Neexistuje univerzální rollback změn databáze v paměti. Modul musí validovat
před zápisem, při složitější operaci si zajistit vlastní zotavení a být
odolný proti opakované inicializaci. Pro vypnutí již provedené serverové
změny slouží restart, který znovu načte původní databázi.

MainMenuBanner registruje pro každý jazyk LazyLoad.AddTransformer. Ten
invaliduje případnou cache; slovníky se nenačítají předčasně. Nadpis se
zachytí při inicializaci a mění se pouze tři konkrétní lokalizační klíče.
Popisy musejí být jedna mezera, nikoliv string.Empty. Ve verzi hry pro SPT
4.1.6 LocalizedText.UpdateLocale vrací řízení před SetLabelText při prázdném
řetězci; původní ruský text uložený v UI pak zůstane viditelný. Regresní test
vyžaduje neprázdný řetězec tvořený pouze bílými znaky u obou popisů.

KLIENTSKÝ MODUL
1. Vytvořte Modules/<Id>/<Id>Module.cs implementující IClientModule.
   ID obsahuje písmena, číslice a podtržítka, začíná písmenem. Je jedinečné.
2. Implementujte Initialize(ClientModuleContext context) a Dispose().
3. Přidejte new <Id>Module() do seznamu host.Start v HeborianPlugin.Awake.
4. Vlastní nastavení definujte přes context.Bind("Key", defaultValue, popis).
   Host automaticky přidá Enabled ve vlastní sekci [Modules.<Id>].
   Klíč Enabled je vyhrazen pro host; modul jej znovu nedefinuje.
5. Pro log použijte context.Log a uvádějte ID. Pro soubory context.Assets.
6. Přidejte test inicializace, vypnutí, selhání a úklidu. UI i prostředky
   ověřte také v běžné hře, samotné testy mimo Unity nemohou ověřit vykreslení.

Ukázka (není součástí spuštěných modulů):
  public sealed class ExampleModule : IClientModule
  {
      public string Id => "Example";
      public void Initialize(ClientModuleContext context)
      {
          var label = context.Bind("Label", "Example", "Popis; restart hry.");
          context.Log.LogInfo("[Example] " + label.Value);
      }
      public void Dispose()
      {
          // Odhlásit události a odstranit vlastní úpravy, pokud byly založeny.
      }
  }

Initialize se spouští na hlavním vlákně Unity v Awake pluginu. Obrazovka menu
nemusí ještě existovat; budoucí UI modul se musí přihlásit na vhodnou událost
nebo použít ověřený patch SPT a v Dispose ho odstranit. Další potřebné reference
(např. spt-reflection nebo Harmony) přidávejte teprve při jejich skutečném
použití, v csproj vždy Private=false, nikdy je nepřibalujte do distribučního ZIPu.

Host vyčistí i modul, jehož inicializace skončila výjimkou, a pokračuje dalším.
Dispose musí být bezpečné i před Initialize, po částečné inicializaci a při
opakovaném volání. Při zániku pluginu se aktivní moduly uklízejí v opačném
pořadí. Každý modul odhlašuje své události, UI objekty, coroutine a patche.
Pro Harmony používejte vlastní ID například local.heborian.client.Example;
nikdy globální UnpatchAll odstraňující patche jiných modů.

PROSTŘEDKY KLIENTA
Soubory uložte do assets/<Id>/ ve zdrojovém projektu. Build je zkopíruje do
BepInEx/plugins/Heborian/assets/<Id>/. Při přidání souborů rozšiřte také
explicitní seznam installFiles v build.ps1: ten hlídá obsah distribučního ZIPu.

  byte[] data = context.Assets.ReadBytes("data.bin");
  Texture2D image = context.Assets.LoadTexture("image.png");

Cesty jsou relativní k vlastnímu adresáři modulu; absolutní cesta nebo výstup
pomocí ../ je odmítnut. Souborová cesta není sandbox proti symlinkům vytvořeným
uživatelem. LoadTexture podporuje formáty PNG/JPEG dostupné v Unity LoadImage.
Chybějící nebo neplatný soubor vyvolá výjimku. Upload textury a její uvolnění
vyžadují hlavní vlákno Unity. Vrácené textury vlastní ModuleAssets: host je
zničí po Dispose modulu nebo po neúspěšné inicializaci. Modul je neničí podruhé
a nepředává je jako sdílený stav jinému modulu. Sprite/GameObject vytvořený
modulem uklízí modul sám před uvolněním jeho textur.

KONFIGURACE A VERZOVÁNÍ
Nová sekce serveru musí mít bezpečné výchozí hodnoty pro starší config.json.
Server konfiguraci při aktualizaci nepřepisuje ani automaticky nemigruje.
Při přejmenování sekce napište konkrétní migraci s její zálohou a testem;
neznámé klíče jsou záměrně odmítány kvůli překlepům. Klient používá BepInEx
ConfigFile a oddělené sekce. Změny za běhu se v této verzi neaplikují.
Při vydání změňte pouze konstantu Version v src/Shared/BuildInfo.cs.
Metadata serveru, BepInPlugin, banner, Directory.Build.props, kompilátor
a názvy ZIPů používají tuto hodnotu. Dokumentaci aktualizujte podle vydání.
Obě DLL obsahují vlastní kompilovanou kopii BuildInfo, nevzniká další závislost.

MODUL HEBORIANMENU (OD 1.2.0)
Používá vlastní Harmony ID local.heborian.client.HeborianMenu a postfix
MenuTaskBar.Awake; již existující lišty vyhledá jednorázově při inicializaci.
Od 1.2.1 klonuje Character toggle a řadí jej před CHARACTER v témže rodiči.
Popisek HEBORIAN přebírá nativní typografii i rozložení. Před aktivací nahradí
klikací event, přidělí vlastní ToggleGroup a vypne původní lokalizaci/tooltip.
Nepřidává umělé hodnoty EMenuType/EEftScreenType do interních slovníků hry.
Obrazovka je samostatná UI vrstva nad aktuálním menu s původní spodní lištou.
BACK je klon nativního DefaultUIButton z inventáře s vlastními posluchači.
Klávesové vstupy přebírá vlastní InputNode přidaný do InputTree pouze po dobu
otevření panelu; Escape zavře panel a zablokuje průchod do menu pod ním.
Od 1.2.1 se strom hledá přes Resources.FindObjectsOfTypeAll a cíl delegátu
aktivního InputManageru. Běžné FindObjectOfType ve skutečném menu vracelo
null. Vyhledávání vylučuje prefab assets a neaktivní manažery; při obalení
delegátu jiným modem se použije strom navázaný na aktivní InputManager.
Dostupnost nadále hlídá Handbook, nikoli Character dostupný také v raidu.
Nativní změna obrazovky nebo klik na původní tab panel zavře. Zánik/disable
lišty i vypnutí modulu odstraní jeho vstup, vlastní objekty a posluchače.
Po zavření zůstává původní obrazovka v původním stavu. Jde o prázdný panel,
nikoliv dosud o datovou stránku nebo o nový vestavěný EFT screen controller.
Rozšíření obsahu patří do HeborianMenuView.EnsurePanel nebo do dalšího
samostatného modulu s explicitní vazbou; neměňte jiné herní obrazovky.

COMMUNITYWAREHOUSE (OD 1.3.0)
Server: WarehouseModule (singleton IServerModule), WarehouseStore (žurnál a
atomický zápis souboru), WarehouseReadRouter a WarehouseItemRouter.
Read je GET /heborian/warehouse s nativním EmptyRequestData. SPT transport
komprimuje odpověď zlib; klient ji čte přes SPT.Common.Http.RequestHandler.
Mutace je ItemRouteAction<WarehouseRequest> s Action="HeborianWarehouse".
Tělo: requestId (GUID N), direction (deposit/withdraw), itemId, revision.
Identita se bere pouze ze session argumentu SPT, nikoli z těla požadavku.

Jeden SemaphoreSlim serializuje všechny požadavky tohoto skladu. Server
ověří profil, vlastnictví, podporovaný typ, revizi a kapacitu. Neakceptuje
klientem dodaná data předmětu. Request ID se ukládají v historii. Zápisy:
1. warehouse.json s Pending a cílovým předmětem profilu;
2. změna profilu v paměti a SaveProfileAsync;
3. změna skladu + historie + revize, vymazání Pending a atomický File.Replace.
Při chybě po zahájení zápisu se modul uzavře. Startup opakuje jen přesun
konkrétní položky, nikdy nepřepisuje celý inventář. Rozpor v datech = fail closed.
Historie zatím není promazávána; obsahuje snapshoty pro diagnostiku.

Klient: samostatný WarehouseClientModule s vlastním životním cyklem.
WarehouseView se kreslí pouze při HeborianMenuView.AnyOpen. GET každé 2 sekundy
jen při otevřeném panelu; mutace přes IEftSession.SendOperationRightNow,
nativní frontu a profileChanges del/new. Lokální profil se ručně nemodifikuje.
Client DTO jsou oddělené od serveru; Newtonsoft, SPT.Common a Unity UI
jsou reference z instalace a nejsou přibalené do ZIPu.
Další etapa: nativní item views/drag-drop, rozdělování stacků, klanové ACL.
Před rozšířením transakcí vždy testovat souběh, replay a recovery.

OD 1.3.1: WarehouseView spravuje síťový stav, WarehousePanel vlastní Unity UI.
HeborianMenuView.ActiveContentRoot poskytuje kořen aktivního obsahu; mimo
otevřený tab vrací null. ActiveTextTemplate poskytuje font nativního tabu.
Modul vytváří UI jako potomka tohoto kořene, před nativním BACK v pořadí
sourozenců. Nepoužívá vlastní Canvas ani IMGUI; dědí vrstvení a raycaster
panelu. Při výměně kořene se UI znovu sestaví, Dispose odstraní své objekty.
Při zavření se automaticky skryje spolu s rodičem. Návrhová plocha 1280 × 800
se škáluje do dostupného obsahu bez deformace čtvercové mřížky. Seznam má
ScrollRect + RectMask2D. Polling beze změny dat zachovává prvky i posun seznamu.
Serverový protokol, ukládání předmětů a pravidla přesunů se v 1.3.1 nemění.

OD 1.3.2: MenuContentLifecycle poskytuje Opened/Updated/Closed. Obrazovka
volá Open synchronně po aktivaci panelu, Tick okamžitě a dále v LateUpdate,
Close při zavření. Odběratelé jsou izolovaní proti výjimkám, chyby se hlásí
přes callback obrazovky. Samostatný startup objekt WarehouseView již není.
WarehouseClientModule registruje spravovaný WarehouseController a při Dispose
všechny tři odběry odhlásí. Controller.Open vytvoří WarehousePanel přímo;
Controller.Tick spravuje polling/UI, Close uvolní UI, Dispose ignoruje
opožděné odpovědi mutací. Při dalším otevření se vytvoří nový panel.
Pro nový obsah použijte stejný životní cyklus a vlastní Dispose; nespoléhejte
na globální polling z objektu založeného před načtením herní scény.
SetContentStatus umožňuje zobrazit chybu a po úspěšném vytvoření UI stav skrýt.

OD 1.4.0: NATIVNÍ ZOBRAZENÍ A ADAPTÉR PŘESUNŮ
NativeWarehouseItem vytváří oddělený Item přes ItemFactory ze serverového
id/template/upd. SnapshotContext a vlastní ItemController jej předají
GridItemView z ItemViewFactory poolu grid_layout. NewGridItemView + Init
zajišťují původní ikony, pozadí a údaje. Není dovoleno použít živý Item
z hráčova inventáře ani předat nativní UI operace proti sdílenému skladu.
Raycasty/layers se při Dispose obnoví, Kill vrátí view do poolu a context
se uvolní. Knihovny a prefaby patří hře a do distribučního ZIPu nevstupují.

WarehousePanel vlastní obě mřížky, wrappery a stav přetahování. Osobní
položky řadí WarehousePacking do osmi sloupců; jde o filtrovaný kompaktní
přehled, nikoli kopii souřadnic stash. Native views jsou virtualizované
podle viditelných řádků. WarehouseItemInput přesměruje kliknutí/drag na
serverový adaptér. UnityEngine.InputLegacyModule je build reference pro Ctrl.
Při drag se polling neaplikuje a pohledy se nerecyklují. Po přesunu se
zahodí starý snapshot a načte nový. Nativní profilové delty zůstávají jedinou
cestou aktualizace skutečného inventáře. Přímé klientské mutace jsou zakázané.

GET nově vrací upd položky. Mutace přijímá volitelné x/y pouze pro deposit;
oba musí být zadány společně. WarehouseStore.PlaceAt kontroluje hranice
a překryvy včetně extrémních integer hodnot před zápisem žurnálu. Bez x/y
platí automatické umístění. Withdraw vždy používá serverové volné místo
v osobním skladu. Schéma uloženého skladu zůstává 1, stará data se nemigrují.
Zbraně/kontejnery, rotace, split/merge, lokální přeskládání a kontextová menu
vyžadují zvláštní návrh protokolu a další transakční testy, nejsou aktivní.

OD 1.4.1: ORGANIZACE SKLADU
Direction=move vyžaduje x/y a položku již přítomnou ve společném skladu.
Stejný gate, kontrola session, revize a requestId jako u převodů. Reposition
kontroluje kolize bez přesouvané položky, vytvoří oddělenou kopii stavu,
přidá auditní záznam a zvýší revizi. Uloží vše jediným atomickým Persist.
Nepoužívá dvoustranný žurnál ani profilové delty, protože vlastník se nemění.
Při chybě zápisu vrátí původní paměťový stav a modul zablokuje do restartu.
Kopie stavu chrání staré auditní záznamy před změnou sdílené reference Entry.
Schéma skladu zůstává 1. Klient určuje move jen při dropu sdílené položky
do sdílené mřížky; withdraw při dropu doprava. Náhled ignoruje vlastní ID,
server vždy kontroluje aktuální stav znovu. Polling rozšíří změnu ostatním.

OD 1.4.3: ROTACE
WarehouseEntry.Rotated (default false) je orientace ve společném skladu;
Width/Height jsou efektivní obsazené rozměry. Staré JSON funguje beze změny.
GET vrací rotated. Deposit a move přijímají volitelné rotated; move bez
hodnoty zachová orientaci. Při změně se rozměry prohodí před kolizní kontrolou.
Json původního předmětu se nemění. Withdraw vybírá místo/orientaci nativně.
Klient mění pouze dragRotated/dragWidth/dragHeight během gesta, snapshot
zůstává neměnný. Nativní ItemView.ItemRotation vykreslí změnu; CancelDrag
obnoví originál, potvrzený serverový snapshot pak vytvoří uloženou orientaci.
R se čte v otevřeném drag stavu s ochranou Time.frameCount proti dvojímu
přepnutí při OnDrag a LateUpdate ve stejném snímku. Uvolnění mimo platný
cíl nepřenáší žádnou operaci na server.

OD 1.4.4: NATIVNÍ MĚŘÍTKO
NativeWarehouseItem.CellPitch = GetCellPixelSize(2,1).X - GetCellPixelSize(1,1).X.
Nezaměňovat s vnějším rozměrem jednoho item view (63 vs 64 v SPT 4.1.6).
WarehousePanel.Resize omezuje návrhové měřítko na CellPitch/Cell, s fallbackem
zmenšení do dostupné plochy. NativeWarehouseItem škáluje opačně Cell/CellPitch,
takže při nativní velikosti nevzniká nadbytečné přepočítání item grafiky.
Pozice, drag náhledy, R rotace a obě texturované mřížky sdílí stejný rodič;
serverové souřadnice jsou stále v celých buňkách, nikoli v pixelech.

OD 1.5.0: ČÁSTEČNÉ PŘEVODY
Request.amount je volitelné celé číslo 1..aktuální StackObjectsCount.
Bez amount nebo při plném počtu platí dosavadní chování. Částečné množství
vyžaduje StackMaxSize > 1. Nová část má nový MongoId, kopii upd a nový počet.
Deposit ukládá do žurnálu ProfileBeforeJson/ProfileAfterJson pro původní ID;
recovery přijímá pouze přesný before nebo již uložený after. Zbytek se vrací
jako ChangedItems. Withdraw ukládá SharedRemainder a novou cílovou položku;
profil dostává NewItems. Vnitřní dělení má Direction=split, SharedRemainder
a nový Entry; ApplyProfile nedělá nic. Všechny varianty používají stávající
gate, revision, requestId, žurnál a atomický Commit. Staré záznamy bez nových
polí zůstávají čitelné. Starý server neumí obnovit rozpracovaný nový split.

WarehousePanel používá klon SplitDialog jako modální vrstvu. Ctrl zachycený
během dragu požádá o množství, Ctrl + kliknutí zůstává rychlý plný převod.
Zdrojová buňka při částečném dělení není uvolněná v kolizním náhledu.

1.5.3 — CURSOR-CELL DROP TARGET
WarehousePanel converts the cursor directly into shared-grid coordinates.
WarehousePacking.DropPosition floors each coordinate and subtracts the grabbed

1.5.5 — CENTERED DRAG
CenterDragOnCursor sets the top-left wrapper offset to half of the current
footprint at BeginDrag and after rotation. The drop anchor is width/2,height/2
(integer division), independent of the original click. Even footprints choose
the right/bottom center cell. Cursor-cell flooring still prevents intra-cell jumps.
This supersedes the grabbed-cell preservation described for version 1.5.3.

WarehousePanel keeps the source tile in place and creates a non-raycast Image

1.6.2 — SOURCE ICON ONLY AND SELF DROP
During drag, NativeWarehouseItem captures and disables every Graphic except
